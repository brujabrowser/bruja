# WASMBlinker

A real Mojo-shaped `LocalFrame` interface -- occupancy subset of
Chromium's published `blink.mojom::LocalFrame` role (browser process
handle to a renderer-side frame). Backed by `LocalFrameImpl` in this
repo: native HTTP GET, HTML parse, classic inline `<script>`, CSS /
layout / paint ([WASMSkia](../WASMSkia) + [WASMRasta](../WASMRasta)
when those siblings are present). Not a stub and not Loki. Occupancy
on **go++ wasigocvm** (`compile.bat` → `wasitime`); host IDL is
[WASMVoodooCompile](../WASMVoodooCompile) `voodoomc`.

```
published chromium/src .mojom     →  voodoomc (host)
interfaces/local_frame.voodoom    →  voodoomc intern  interface:blink.LocalFrame
LocalFrameImpl                    →  parse / script / layout / paint
C ABI blink/c/frame.h             →  BlinkerLoadHTML / Navigate / Eval
```

Classic inline `<script>` tags run in document order on Navigate/LoadHTML
(matching Blink's parser-blocking scripts). `src=` / `type=module` /
`defer`/`async` are skipped (documented, not silently mis-run). A throwing
script does not abort later ones.

[WASMRenderer](../WASMRenderer) `CreateFrame()` is the include hop that
hands back `pending_remote<LocalFrame>` onto this `LocalFrameImpl`.
[WASMLime](../WASMLime) Context/Frame occupy that remote. Not Loki.

## Why this isn't a literal blink.mojom port

Published `blink.mojom.LocalFrame` is hundreds of methods with no stable
embedder ABI. `interfaces/local_frame.voodoom` occupies the Navigate /
LoadHTML / Eval / paint hop `LocalFrameImpl` actually implements.
`voodoomc` intern is `interface:blink.LocalFrame`.

## What's wired vs. stubbed

| Area | Status |
|---|---|
| `LocalFrame.Navigate`/`LoadHTML`/`CaptureSnapshot`/`Eval` Mojo request/response, over a real pipe (`Proxy_`/`Stub_`, generated by voodoomc) | Wired 1:1 |
| `LocalFrameImpl::Navigate`/`LoadHTML` → real HTTP GET (`blink/http_client.cc`) → native HTML parse + classic inline `<script>` execution (Blink parser-blocking scripts) + CSS/layout/paint | Wired -- see `tests/local_frame_roundtrip_test.cc` |
| Per-frame identity (`frame_id` ties every `Navigate()` on one `LocalFrameImpl` to the same in-process engine -- DOM/Storage persist across calls) | Wired |
| wasigocvm networking | Product machine is go++ wasigocvm (sockets in-module). Stock wasi-sdk Preview 1 leftover: `HttpGet` returns `connected=false`. `LoadHTML` and generated `Proxy_`/`Stub_` still run. |
| Punched-UDP transport to a real out-of-process renderer (vs. the plain-HTTP renderer bridge) | **Not wired** -- see WASMThunker's own "Invitations are loopback-only" section; the same gap applies one rung up here |

## Public headers

`interfaces/local_frame.voodoom` is compiled by `voodoomc` (from the
sibling `WASMVoodooCompile` checkout) into `local_frame_interface_gen.h`
at build time -- see CMakeLists.txt. `include/blink/local_frame_impl.h`
and `include/blink/http_client.h` are this repo's own code.

## Build (native, Windows)

MinGW g++ or MSVC. Requires sibling checkouts of `../WASMVoodooCompile`
(itself requiring `../WASMCadidumBindings` and `../WASMCadidumKernel`).

```
cmake -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

When built from [WASMv16](../WASMv16) or [WASMLime](../WASMLime) (so
`wasmv16_engine` / `bruja_dom` / `wasmskia_font` exist before blinker is
configured), the round-trip tests also cover classic `<script>` execution,
the mirrored DOM, and real paint. Paint loads Segoe UI (or Arial) plus
`seguiemj.ttf` / `seguisym.ttf` fallbacks so emoji render as COLR color
glyphs instead of `.notdef` tofu squares.

## WASM (wasigocvm)

Product occupancy is go++ wasigocvm, not stock wasmtime Preview 1.
`blinker_wasm` is a reactor: generated `Proxy_`/`Stub_` from
`interfaces/local_frame.voodoom` (host `voodoomc`) linked with `wcb` and
`LocalFrameImpl`. The C ABI in `include/blink/c/frame.h`
(`BlinkerLoadHTML` / `BlinkerNavigate` / `BlinkerEval`) talks through that
generated Mojo path -- the same `Remote`/`Receiver` loopback the native
golden tests use -- not a second implementation.

`voodoomc` itself does not run in the guest. Configure with a native
generator (`-DWASIGO_GOCVM=1` when using the go++ wasigocvm toolchain):

```
cmake -B build-wasi -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/wasi-sdk.cmake -DVOODOOMC_HOST=../WASMVoodooCompile/build/voodoomc.exe
cmake --build build-wasi --target blinker_wasm
```

`LoadHTML` / parse / layout work in the guest. `Navigate()`'s HTTP GET is
an honest `connected=false` error under WASI (preview1 has no
`getaddrinfo`/`connect`; same shape as the existing `https://` rejection).
`Eval` is the existing honest stub unless `wasmv16_engine` is already a
target. Paint stays the existing honest stub unless WASMSkia/WASMRasta
are already targets.
